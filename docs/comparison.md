# Сравнение с APT

Проверено 06.11.2026 на Ubuntu 24.04 в GitHub Actions: все нормализованные
обязательные рёбра совпали для трёх пакетов. Сохранённые результаты находятся
в native-apt/results.json, исходные выводы apt-cache — в native-apt/*.

Используется один и тот же индекс Ubuntu noble/main/binary-amd64 для программы
и apt-cache. Системные источники и установленные пакеты не подмешиваются:
скрипт создаёт временное состояние APT с единственным локальным индексом.
Условный адрес localhost в sources.list нужен для сопоставления файла индекса;
apt-cache не обновляет источники и не обращается по этому адресу в сеть.

## Воспроизведение

В Linux с Python 3.12+ и установленным apt:

```sh
python3 scripts/compare_apt.py
```

Скрипт запускается также в GitHub Actions. Результаты и исходный DOT сохраняются
в артефакте native-apt-comparison. APT применяется только для внешней проверки;
код src/apt_graph не запускает apt-cache, apt, dpkg или сторонние парсеры.

Проверяются полные графы следующих пакетов из базового noble:

| Пакет | Версия | Вершины программы | Рёбра программы |
| --- | --- | --- | --- |
| bash | 5.2.21-2ubuntu4 | 15 | 27 |
| coreutils | 9.4-3ubuntu6 | 10 | 16 |
| grep | 3.11-4build1 | 5 | 6 |

Для каждой вершины выполняется `apt-cache depends --important ИМЯ=ВЕРСИЯ`.
Сравниваются все конкретные непосредственные зависимости, включая поставщиков
виртуальных пакетов. Несовпадение останавливает проверку с ошибкой.
Собственное сравнение версий отдельно проверяется против dpkg на 400 парах.

## Сравнение визуализаций

`apt-cache dotty ИМЯ` формирует штатное представление графа в DOT.
Скрипт сохраняет эти исходники рядом с результатами проверки.
Наши examples/*.puml — представления того же анализа в PlantUML.

Рисунки могут отличаться по следующим причинам:

- dotty включает отношения конфликтов (зелёные рёбра), а приложение строит
  только обязательные Depends и Pre-Depends;
- dotty показывает виртуальные пакеты отдельными вершинами; приложение
  заменяет такую вершину доступными поставщиками (например, awk — gawk и mawk);
- приложение подписывает конкретные версии; dotty в основном подписывает имена;
- в демонстрационных командах README глубина 2, а сравнение строит полный граф;
- APT выбирает один вариант для установки, но граф показывает все доступные
  варианты удовлетворения зависимости. Это не симулятор установки пакетов.

Поэтому сравниваются нормализованные обязательные рёбра через depends,
а не равенство двух рисунков или количество всех рёбер исходного DOT.

В сохранённом DOT получено 40 рёбер для bash, 37 для coreutils и 25 для grep;
в нормализованных графах обязательных зависимостей — 27, 16 и 6 соответственно.

Документация штатного инструмента:
https://manpages.ubuntu.com/manpages/noble/man8/apt-cache.8.html
